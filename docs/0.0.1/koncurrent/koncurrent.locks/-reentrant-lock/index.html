ReentrantLock

expect class ReentrantLock : Lock(source)

A mutual exclusion lock that the thread holding it can take again.

Only one thread holds the lock at a time. That thread can call lock again without waiting. It must then call unlock once for each lock. Prefer withLock, which never forgets to unlock.

The lock is not fair unless it is created so. A thread that asks for a free lock then takes it, even when other threads wait for it. A fair lock goes to the thread that has waited for the longest. No thread waits forever for it, and it is much slower when many threads take it, since every release wakes a thread up.

The lock holds no native resource. It has nothing to close, and it is freed as any object.

Platforms

  • On the JVM and Android this is java.util.concurrent.locks.ReentrantLock.

  • On native this is a port of the ReentrantLock of JSR-166. A thread that waits sleeps until the lock is released.

  • JS and Wasm have one thread, which never waits. The lock only counts its holds there.
