StampedLock

actual class StampedLock(source)

A lock with three modes: writing, reading and optimistic reading. Each lock that it grants comes with a stamp, a number that releases the lock or turns it into another mode.

  • Writing. writeLock waits until no thread holds the lock, then holds it alone.

  • Reading. readLock waits while a thread writes. Many threads read at once.

  • Optimistic reading. tryOptimisticRead takes no lock and never waits. It returns a stamp, and validate tells later whether a thread wrote since.

An optimistic read suits short sections that only read, where writes are rare. It copies what it needs, then validates, and uses the copies only when the stamp is still valid. What it read may be half written until then.

var stamp = lock.tryOptimisticRead()
var x = point.x
var y = point.y

if (!lock.validate(stamp)) {
    stamp = lock.readLock()

    try {
        x = point.x
        y = point.y
    } finally {
        lock.unlockRead(stamp)
    }
}

The stamp of a lock that was granted is never zero. The functions that try return zero when they fail.

read and write run a block under a lock, and never forget to release it. asReadLock, asWriteLock and asReadWriteLock give the lock to code that expects a Lock or a ReadWriteLock, without its stamps.

The lock is not reentrant. A thread that holds it and asks for it again waits for itself. It has no owner either, so a thread can release what another one acquired, with its stamp. And it has no condition.

A thread that asks for a free lock takes it, even when other threads wait. The lock does not always prefer the readers or the writers.

Platforms

  • On the JVM this is java.util.concurrent.locks.StampedLock.

  • On Android this is the platform lock from API 24, where it appeared, and the port of native below.

  • On native this is a port of the StampedLock of JSR-166.

  • JS and Wasm have one thread, which never waits. A lock that is not granted at once never could be, so writeLock and readLock throw IllegalStateException then.
