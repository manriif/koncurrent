ReentrantReadWriteLock

expect class ReentrantReadWriteLock : ReadWriteLock(source)

A pair of locks over the same data: a read lock that many threads hold at once, and a write lock that one thread holds alone.

It suits data that is read far more often than it is changed. Readers do not wait for each other. A writer waits until no thread reads, and readers wait while a thread writes. Prefer read and write, which never forget to unlock.

Both locks are reentrant. The thread that writes can also take the read lock, and keep it after it released the write lock. The opposite is not possible. A thread that holds the read lock must release it before it takes the write lock, or it waits for itself forever. write does that for its caller.

The lock is not fair unless it is created so. A thread that asks for a free lock then takes it, even when other threads wait. One rule keeps writers from starving. A thread that does not read yet lets a waiting writer pass first. A fair lock goes to the threads in the order of their arrival, which is slower when many threads take it.

Platforms

  • On the JVM and Android this is java.util.concurrent.locks.ReentrantReadWriteLock.

  • On native this is a port of the ReentrantReadWriteLock of JSR-166.

  • JS and Wasm have one thread, which never waits. The locks only count their holds there. Taking the write lock while holding only the read lock throws IllegalStateException, since it could never succeed.
