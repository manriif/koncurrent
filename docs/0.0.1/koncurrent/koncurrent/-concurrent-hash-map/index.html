ConcurrentHashMap

actual class ConcurrentHashMap<K : Any, V : Any> : MutableMap<K, V> (source)

A hash map that any number of threads can read and update at the same time.

Lookups never block. An update only locks the bin of its key, so updates of different keys rarely wait for each other. Keys and values cannot be null.

The functions that update one key are atomic: put, remove, putIfAbsent, replace, computeIfAbsent, computeIfPresent, compute and merge. The bulk functions are not. Other threads may see a putAll or a clear half done. size, isEmpty and containsValue give a transient state while other threads update the map.

keys, values and entries are views of the map. Their iterators are weakly consistent. They never throw ConcurrentModificationException. They visit once each element that existed when they were created, and may or may not reflect later updates.

The standard getOrPut is not atomic on this map. Use computeIfAbsent.

A function given to computeIfAbsent, computeIfPresent, compute or merge must not update this map. Other updates of the same bin wait for it, so it should be short.

Platforms

  • On the JVM this is java.util.concurrent.ConcurrentHashMap.

  • On Android this wraps the platform map from API 24, and a port of it below. The platform map has no atomic computation before API 24.

  • Elsewhere this is a port of the ConcurrentHashMap of JSR-166.
