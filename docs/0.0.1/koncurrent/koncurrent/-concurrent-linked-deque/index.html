ConcurrentLinkedDeque

expect class ConcurrentLinkedDeque<E : Any> : Deque<E> (source)

A Deque without a capacity that several threads use at once, at both ends. An operation never waits for an element nor for room: pollFirst and pollLast return null when the deque is empty.

An iterator is weakly consistent. It never throws ConcurrentModificationException, and it may or may not show the elements added or removed since it was created.

Platforms

  • On the JVM and Android this is java.util.concurrent.ConcurrentLinkedDeque, which is lock-free. Its size is counted by going through the elements.

  • Elsewhere this is a ring of elements that one lock guards. Kotlin cannot update a field of a node atomically, and the lock-free queue was measured several times slower without it. No operation holds the lock for long, except contains, remove of an element and the creation of an iterator, which go through the elements.
