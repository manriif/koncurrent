Semaphore

expect class Semaphore(source)

A count of permits that threads take and give back. It limits how many threads use a resource at once, like the connections of a pool.

acquire takes a permit, and waits while there is none. release gives one back, and wakes up a waiting thread. Prefer withPermit, which never forgets to release.

A permit does not belong to a thread. Any thread can release, whether it acquired or not. So a semaphore also serves as a signal between threads: one waits in acquire until another calls release.

The semaphore is not fair unless it is created so. A thread that asks for a permit then takes one if there is any, even when other threads wait. The permits of a fair semaphore go to the threads in the order of their arrival.

Platforms

  • On the JVM and Android this is java.util.concurrent.Semaphore.

  • On native this is a port of the Semaphore of JSR-166.

  • JS and Wasm have one thread. An acquire without a permit could never end, so it throws IllegalStateException there.

Parameters

permits

the number of permits at the start. It may be negative, in which case releases must come before any permit can be acquired.
