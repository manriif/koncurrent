ArrayBlockingQueue

expect class ArrayBlockingQueue<E : Any> : BlockingQueue<E> (source)

A BlockingQueue on an array of fixed size, in the order of arrival: the head is the element that has been in the queue for the longest time.

Its capacity is set once. A full queue makes put wait, and an empty one makes take wait. A fair queue serves the threads that wait in the order of their arrival, which is slower. It allocates nothing once created, where LinkedBlockingQueue allocates a node for each element. One lock guards both ends, so the threads that add and those that take wait for each other.

An iterator is weakly consistent. It never throws ConcurrentModificationException, and it may or may not show the elements added or removed since it was created.

Platforms

  • On the JVM and Android this is java.util.concurrent.ArrayBlockingQueue.

  • Elsewhere this is a port of the ArrayBlockingQueue of JSR-166. Its iterator goes through the elements as they were when it was created.

  • JS and Wasm have one thread, which nothing could wake up. put on a full queue and take on an empty one throw IllegalStateException there.
